## MIGRATION STRATEGY

### Phase 1: Package Upgrades

**Why required:** The current `@midnight-ntwrk/compact-runtime@^0.14.0` is incompatible with v0.23 compiled output. SDK v3.x packages must be upgraded to v4.x to match the reference implementation.

**Files that change:**
- `frontend/package.json` — update version numbers
- `package.json` (root) — update version numbers (if used by deploy scripts)
- `node_modules/` — regenerated by npm install

**Files that must NOT change:**
- All React component files
- All context files
- All provider files
- All TypeScript source files

**Package changes:**

Remove:
- `@midnight-ntwrk/compact-runtime` (consumed indirectly via `@midnight-ntwrk/midnight-js-protocol`)

Add:
- `@midnight-ntwrk/compact-js` (if not present — required for `CompiledContract.make()`)

Upgrade:
| Package | From | To |
|---|---|---|
| `@midnight-ntwrk/midnight-js-contracts` | `^3.0.0` | `^4.1.1` |
| `@midnight-ntwrk/midnight-js-fetch-zk-config-provider` | `^3.0.0` | `^4.1.1` |
| `@midnight-ntwrk/midnight-js-http-client-proof-provider` | `^3.0.0` | `^4.1.1` |
| `@midnight-ntwrk/midnight-js-indexer-public-data-provider` | `^3.0.0` | `^4.1.1` |
| `@midnight-ntwrk/midnight-js-network-id` | `^3.0.0` | `^4.1.1` |
| `@midnight-ntwrk/midnight-js-types` | `^3.0.0` | `^4.1.1` |
| `@midnight-ntwrk/compact-runtime` | `^0.14.0` | Remove (replaced by protocol) |

**Risks:**
- SDK v4.x may have breaking API changes in provider interfaces
- The `initializeProviders()` function in `midnight-providers.ts` may need updates for v4.x provider shapes
- `UnboundTransaction` type may have changed between v3 and v4
- `Transaction.deserialize()` signature may differ

---

### Phase 2: Compiler Installation

**Why required:** The current compiled artifacts were generated by Compact v0.14 which produces metadata-only output. v0.31.1 produces the `Contract` class that `CompiledContract.make()` requires.

**Files that change:**
- None yet — the compiler binary is installed globally

**Files that must NOT change:**
- All source files

**Steps:**
1. Download `compactc_v0.31.1_x86_64-unknown-linux-musl.zip` from GitHub Releases:
   https://github.com/LFDT-Minokawa/compact/releases/tag/compactc-v0.31.1
2. Extract binary to project root or add to PATH
3. Verify: `compactc --version` shows `0.31.1`

**Alternative:** Use WSL on Windows or a Docker container with the compactc binary installed.

**Risks:**
- Windows does not natively support the Linux binary — requires WSL or Docker
- Compilation may produce different circuit sizes (k, rows) than v0.14
- New compiler may have different CLI flags

---

### Phase 3: Contract Regeneration

**Why required:** The `membership.compact` source must be recompiled with v0.31.1 to produce a `Contract` class.

**Files that change:**
- `contracts/Membership.compact` — update pragma line only:
  - Before: `pragma language_version >= 0.14.0;`
  - After: `pragma language_version 0.23;`

**Files that are regenerated (complete replace):**
- `managed/Membership/contract/index.cjs`
- `managed/Membership/contract/index.d.ts`
- `managed/Membership/compiler/contract.json`
- `managed/Membership/keys/registerMember.pk`
- `managed/Membership/keys/registerMember.vk`
- `managed/Membership/zkir/registerMember.zkir`

**Files that must NOT change:**
- `frontend/src/lib/compiled-contract.ts` — import logic stays the same
- `frontend/src/lib/contract.ts` — type definitions may need updating if shapes change
- `frontend/src/context/ContractContext.tsx` — business logic stays
- `frontend/src/App.tsx` — UI stays
- `frontend/src/lib/midnight-providers.ts` — provider wiring stays

**Compilation command:**
```bash
compactc compile contracts/Membership.compact managed/Membership
```
(Node.js equivalent via `scripts/compile.ts` will also work if updated)

**Risks:**
- The compiler may reject `Counter` type or other v0.14 constructs — the `Counter` in `Membership.compact` is a user-defined struct, not a native type, so it should compile fine with v0.23
- The compiler may produce different circuit parameters (k value, rows) — verify they match
- The generated `Contract` class will have `checkRuntimeVersion('0.16.0')` — this requires runtime v0.16.x+

### Phase 4: Artifact Synchronization

**Why required:** The generated artifacts must be copied to all locations the frontend expects them.

**Files that change:**

Source → Destination:
```
managed/Membership/contract/index.cjs       → frontend/src/managed/Membership/contract/index.cjs
managed/Membership/contract/index.d.ts       → frontend/src/managed/Membership/contract/index.d.ts
managed/Membership/compiler/contract.json    → frontend/src/managed/Membership/compiler/contract.json
managed/Membership/keys/*                    → frontend/src/managed/Membership/keys/*
managed/Membership/zkir/*                    → frontend/src/managed/Membership/zkir/*
```

Then from `frontend/src/managed/` → `frontend/public/managed/` (static serving).

Also sync to root `managed/` if the root `package.json` scripts reference it.

**Files that must NOT change:**
- N/A — this is a copy operation

**Risks:**
- Missing copy steps will cause runtime 404 errors for ZK artifacts
- The `index.cjs` extension matters — CJS is expected by the import in `compiled-contract.ts`
- The `keys/` directory must contain `.pk`, `.vk`, `.prover`, or `.verifier` files — verify the new compiler's output extensions

### Phase 5: Verification

**Why required:** Ensure the complete pipeline works end-to-end.

**Verification steps:**

1. **Build verification:**
   ```bash
   cd frontend && npm run build
   ```
   Confirm zero TypeScript errors and successful bundle output.

2. **Unit test: Contract class detection:**
   Create a minimal Node.js script (or update a test):
   ```js
   const cjs = require('./frontend/src/managed/Membership/contract/index.cjs');
   console.log('Contract typeof:', typeof cjs.Contract);         // Must be 'function'
   console.log('Contract is class:', /^class/.test(cjs.Contract.toString())); // true
   ```

3. **Runtime test: CompiledContract.make()**
   ```js
   const { CompiledContract } = require('@midnight-ntwrk/compact-js');
   const cjs = require('./frontend/src/managed/Membership/contract/index.cjs');
   const cc = CompiledContract.make('Membership', cjs.Contract);
   console.log('CompiledContract created:', !!cc); // Must be truthy
   ```

4. **Browser test:**
   - Start dev server: `cd frontend && npm run dev`
   - Connect wallet
   - Click "Deploy New Contract Instance"
   - Confirm no `TypeError: o.ctor is not a constructor`
   - Confirm deploy completes successfully

5. **Circuit execution test:**
   - After deploy, enter a numeric secret
   - Click "Execute ZK Circuit"
   - Confirm Lace opens balance & sign
   - Confirm success state

**Files that must NOT change:**
- All source files — verification is read-only

**Risks:**
- SDK v4.x API changes in provider interfaces may cause runtime errors
- `Transaction.deserialize()` signature may differ between SDK v3 and v4
- `balanceTx` and `submitTx` provider methods may have changed signatures

## SUMMARY: Minimal Change Set

The absolute minimum changes to fix `o.ctor is not a constructor`:

1. **`contracts/Membership.compact`** — change pragma from `>= 0.14.0` to `0.23`
2. **`frontend/package.json`** — upgrade all `@midnight-ntwrk/*` packages from `^3.x` to `^4.1.1`, remove `@midnight-ntwrk/compact-runtime`, add `@midnight-ntwrk/compact-js`
3. **Install compactc v0.31.1** and recompile the contract
4. **Sync artifacts** to all managed directories
5. **`cd frontend && npm install`** to update lockfile
6. **Test** build and runtime

No React components, no context APIs, no providers, no business logic changes needed.
